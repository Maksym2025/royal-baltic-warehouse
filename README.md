# Royal Baltic Warehouse Lab

Полный локальный экспорт существующего прототипа склада. Проект: `royal-baltic-warehouse`.
React + TypeScript + Vite. Интерфейс перенесён из последней подготовленной версии `feat/warehouse-ui-audit`, коммит `110dd143a35bfb28f7c639db1ac9c54853750894` от 27.10.2026. Опубликованная версия Sites этим экспортом не заменяется.

## Запуск на Windows

1. Установите **Node.js 24 LTS** (или Node.js 22.12+); npm входит в установку. Официальный установщик: https://nodejs.org/ .
2. Создайте папку `C:\Projects\RoyalBaltic\warehouse`.
3. Распакуйте **содержимое ZIP** прямо в эту папку. `package.json` должен находиться по адресу `C:\Projects\RoyalBaltic\warehouse\package.json`.
4. Откройте Терминал / PowerShell:

```powershell
cd C:\Projects\RoyalBaltic\warehouse
npm install
npm run dev
```

Откройте **http://localhost:5173/**. Остановить сервер: `Ctrl+C`.

Если PowerShell запрещает запуск `npm.ps1`, используйте `npm.cmd install` и `npm.cmd run dev` либо командную строку CMD. Менять системную ExecutionPolicy не нужно.

Если порт 5173 занят, остановите другой процесс или используйте `npm run dev -- --port 5174`. Новый порт создаёт отдельное хранилище браузера; инструкция переноса данных находится ниже.

## Сборка и проверки

```powershell
npm test
npm run build
npm run preview
```

`npm run build` проверяет TypeScript и создаёт статические файлы в `dist`. `npm run preview` открывает результат на **http://localhost:4173/**. Сборка ничего не публикует. `npm run check` запускает тесты и сборку вместе.

В ZIP-архиве также есть проверенная сборка `dist`; при клонировании GitHub-репозитория она создаётся командой `npm run build`. Исходный самостоятельный HTML сохранён как `reference/royal-baltic-warehouse-ui.html`: его можно открыть без Node.js для сравнения исходного интерфейса. Разработка React-версии ведётся в `src`.

Тесты и сборка проверены в Linux на Node.js 24.22.1; непосредственно на Windows не запускались. Команды не используют Python, Bash, Linux-пути или переменные окружения shell. `package-lock.json` содержит публичные npm-адреса и зависимости для Windows; `node_modules` намеренно не включён.

## Данные и сценарии

Сохранены три исходных товара, два стартовых заказа, журнал и переключатель демонстрационных ролей. Старт: **450 кг физически / 40 кг в резерве / 410 кг свободно**. JSON стартового примера: `data/demo-state.json`.

- Физический остаток = начальный остаток + приходы − фактически отгруженное.
- Создание черновика не создаёт резерв и не списывает товар.
- Подтверждение заказа резервирует товар; нехватка свободного остатка блокирует подтверждение.
- Оплата не меняет остатки и не выдаёт разрешение.
- Только роль `root` выдаёт разрешение; само разрешение остатки не меняет.
- Менеджер может отгрузить только после разрешения root admin. Модуль операций проверяет это отдельно от состояния кнопки.
- Отгрузка уменьшает физический остаток и резерв один раз. Доставка повторно ничего не списывает.
- Отмена до отгрузки освобождает резерв и отзывает разрешение.

Исходное поведение разрешения сохранено: root admin может осознанно разрешить отгрузку даже при неотмеченной оплате; диалог показывает статус оплаты. Новое обязательное условие оплаты не добавлялось.

Данные сохраняются **только в localStorage браузера** с исходным ключом `royal-baltic-warehouse-v1`, схема `version: 1`. Поддержаны прежняя проверка сохранённых данных, журнал «до → после», синхронизация между вкладками и отказ от операции при ошибке сохранения.

Данные, введённые вами на домене Sites, не входят в исходный код и не могут автоматически появиться на localhost: браузер разделяет хранилища по адресу/порту. Для переноса без потери истории см. **[docs/DATA-TRANSFER.md](docs/DATA-TRANSFER.md)**. Архив содержит исходные демонстрационные данные, а не неизвестную историю из вашего браузера.

## Изоляция

Это демонстрационный локальный клиент, без API, ключей, backend и подключения к Neon/Supabase. Переключение ролей — намеренная симуляция, а не настоящая серверная авторизация: владелец браузера может менять клиентские данные. Правила операций соблюдаются внутри выбранной роли; превращать демо в реальный многопользовательский склад без серверных проверок нельзя.

Сервер разработки привязан к localhost. В конфигурации разрешено также имя `terminal.local` для внутренней проверки экспорта; это не включает внешний хостинг. Защита владельцем ChatGPT относится к размещённому Sites, а не является частью локального приложения. CRM, домены royal-baltic.eu / royal-baltic.com и production-базы не менялись. В проекте нет команды deploy или GitHub Actions. Загрузка исходников на GitHub сама по себе не публикует приложение.

## GitHub и клонирование

Исходники: https://github.com/Maksym2025/royal-baltic-warehouse

Репозиторий создан владельцем как публичный. При первой загрузке 27.10.2026 публичность сохранена по его прямому указанию; перевод в Private владелец выполнит отдельно. Проверьте актуальную видимость в GitHub Settings.

Если целевой папки ещё нет, можно получить проект без ZIP:

```powershell
cd C:\Projects\RoyalBaltic
git clone https://github.com/Maksym2025/royal-baltic-warehouse.git warehouse
cd warehouse
npm install
npm run dev
```

Если вы уже распаковали ZIP в `warehouse`, используйте имеющиеся файлы или клонируйте в другую пустую папку. После перевода репозитория в Private для клонирования потребуется авторизация GitHub.

Демо-резервные копии, `.env`, `node_modules` и результат сборки `dist` исключены из Git. Проверки запускаются локально через `npm run check`.
