# Инфраструктура дизайна

Существующие макет, цвета, размеры и поведение сохранены. Это перенос, не редизайн.

## Что настроено

- React 19 + строгая проверка TypeScript + Vite.
- Tailwind CSS 4 через `@tailwindcss/vite`.
- shadcn/ui: `components.json`, `tsx: true`, `rsc: false`, стиль `new-york`, алиасы компонентов, `cn()` из `clsx` и `tailwind-merge`.
- Реестр `@bklit`: `https://ui.bklit.com/r/{name}.json`.
- Семантические токены shadcn и `--chart-1` … `--chart-5` сопоставлены с текущей палитрой.
- Единственный компонент в `components/ui` — реально используемый `Button`, адаптированный к исходным CSS-классам. Это локальная реализация в соглашениях shadcn, не неизменённая копия библиотечного Button.

Новые библиотеки диалогов, таблиц, иконок и графиков не устанавливались. Существующий модальный интерфейс использует `<dialog>` и React; таблицы семантические HTML.

## Добавление компонентов позже

Проект уже сконфигурирован; `shadcn init` повторно запускать не требуется: он может перезаписать стили.

В корне проекта, только когда компонент действительно нужен:

```powershell
npx shadcn@latest add @bklit/line-chart
```

Эта команда пока **не выполнялась**. После её выполнения проверьте изменения `package.json`, CSS и созданные импорты; выполните `npm run check`. Не перезаписывайте существующую кнопку командой `add button` без сравнения изменений.

Для остатков, резервов, приходов и разрешений сохраняются точные таблицы. Для временных рядов остатков подходит line chart; для приходов/отгрузок по дням — grouped bar chart. Данные для будущих графиков берутся из реально записанных событий, без придуманной истории.

## Сохранение оформления

`warehouse.css` совпадает с исходником. В Tailwind подключены theme и utilities **без Preflight**, чтобы не поменять стандартные отступы, размеры шрифтов и элементы текущего интерфейса. Новому компоненту может потребоваться локальное оформление; не включайте глобальный reset без визуального сравнения.

Исходный `--muted` — цвет текста. Его значение сохранено; Tailwind `bg-muted` сопоставлен с `--soft`, `text-muted-foreground` — с прежним `--muted`.

## UI UX Pro Max и Emil Design Skills

Эти навыки относятся к инструменту разработки/AI-агенту, не к runtime React. Их не нужно добавлять в `dependencies`.

1. Откройте `C:\Projects\RoyalBaltic\warehouse` как корневую папку проекта в вашем редакторе/агенте.
2. Подключите настоящие установленные пакеты UI UX Pro Max и Emil Design Skills штатным способом этого инструмента. Если инструмент работает с файлами навыков, используйте его документированный каталог и оригинальные `SKILL.md` с зависимыми файлами из доверенного источника.
3. Дайте агенту `AGENTS.md`, этот файл и `docs/UI-AUDIT-PLAN.md` как контекст.
4. Попросите сначала аудит/план, затем работу в отдельной ветке; эталон в `reference/` позволяет сравнить результат.

Архив не содержит поддельных SKILL.md, установщиков сторонних навыков или заявления, что эти навыки уже установлены на вашем компьютере. Никаких специальных интеграций с runtime для их последующего использования не требуется.
